# Phase 1 实施与验收计划

依据 `requirements.md` 的 Phase 1 和用户本次授权实施。Phase 1 验收通过后自动进入 Phase 2；真实外部服务器验收缺少条件时，报告缺项，不把协议测试当作外部验收。

## 设计

- Rust/Tokio/russh 处理 TCP、握手、主机身份、认证和交互 PTY；应用级接口通过 UniFFI 暴露，不把 russh 类型传给 SwiftUI。
- 每个终端标签持有独立会话和 SwiftTerm 视图。状态事件与原始输出字节通过有界队列批量读取；输入有界，resize 合并为最新值；任何阶段均可取消。关闭标签释放网络任务，远程断开与本地主动断开区分。
- 未知主机先显示算法与 SHA256 指纹，由用户明确确认后认证；本机记录已信任公钥，后续不匹配强制阻断。自动集成测试仅使用从可信服务器配置直接取得的预置指纹。
- 密码、私钥和口令仅在内存中使用。Swift 从系统文件选择器读取授权文件字节，Rust 不接收沙盒外文件路径。Phase 2 再加入 Keychain 凭据保存与 SwiftData 主机管理。
- 错误使用稳定代码映射到中英 String Catalog，不将库错误、凭据或远程终端内容写入日志。原生终端保留 ANSI/UTF-8 和动态窗口尺寸；远程 OSC 不允许读取剪贴板或触发自动外链。

选择有界事件轮询而非跨线程 Swift 回调，是为了简化 Swift 6 隔离、取消和对象所有权；轮询只取现成事件，网络与等待始终在 Tokio 上执行。

## 执行顺序

1. 固定依赖，先写验证输入、主机指纹策略、超时与取消的失败测试。
2. 完成 Rust 会话及可重复的协议/真实 SSH 集成测试。
3. UniFFI 生成绑定并构建四个 Apple 架构。
4. 连接表单、主机信任确认、标签状态、SwiftTerm delegate/feed/resize 和移动端键盘。
5. 运行 Rust 检查与测试、双端构建、三端测试/截图；记录外部服务器验收条件与实测结果。
